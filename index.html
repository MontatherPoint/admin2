نطاق تطبيق الإدارة

تطبيق المدير مخصص لمستخدم يحمل الدور admin، ويجمع متابعة المشاريع والمهندسين والموارد والمالية. هذا الملف مستقل عن أدلة المهندس والمحاسب، ويمكن استخدامه أساسًا لتطبيق منفصل أو flavor إداري.

المشاريع والعمللوحة المدير، المواقع، خطط العمل، تحديثات المهام، التقارير اليومية ومراجعتها.
المواردالمهندسون والمستخدمون، الآليات، المخزون، حركات المخزن، طلبات التصليح وقطع الغيار.
الماليةدليل الحسابات، القيود اليومية، تفاصيل القيود، ميزان المراجعة وملخص النتائج المالية.
المتابعةالإشعارات، الترتيب اليومي للمهندسين، تصدير التقارير من واجهة الويب الحالية.
حدود الأدوار: كل المسارات في management.php تتطلب admin. واجهة الحسابات المنفصلة لها دور accountant وملف API مستقل. المخزن والصيانة يستخدمان صلاحية المدير حاليًا.

الإعداد والدخول

استبدل YOUR_DOMAIN بنطاق HTTPS المنشور عليه نظام Maxlond، وأضف مسار المجلد إذا لم يكن التطبيق في جذر النطاق.

Auth:       https://YOUR_DOMAIN/api/auth.php?route=
Management: https://YOUR_DOMAIN/api/management.php?route=

الدخول: POST /api/auth.php?route=login. أرسل Accept: application/json وContent-Type: application/json وجسمًا بهذا الشكل:

{
	"username": "admin.username",
	"password": "PASSWORD",
	"device_info": "Maxlond Management / iOS"
}

اقبل الاستجابة فقط إذا كان data.user.role == "admin". خزّن data.token في flutter_secure_storage، وأرفقه بكل طلب محمي:

Authorization: Bearer <token>
Accept: application/json
Content-Type: application/json

التوكن صالح 30 يومًا ولا توجد نقطة refresh. نفّذ الخروج عبر POST /api/auth.php?route=logout ثم احذف التوكن محليًا. لا تضع كلمة مرور افتراضية أو توكن ثابت في التطبيق.

عميل API

import 'dart:convert';
import 'package:flutter_secure_storage/flutter_secure_storage.dart';
import 'package:http/http.dart' as http;

class ApiException implements Exception {
	const ApiException(this.statusCode, this.code, this.message);
	final int statusCode;
	final String code;
	final String message;
}

class AdminApi {
	AdminApi(String origin, {http.Client? client})
			: _origin = origin,
				_client = client ?? http.Client();

	final String _origin;
	final http.Client _client;
	final _storage = const FlutterSecureStorage();

	Uri _uri(String route, [Map<String, String> query = const {}]) =>
			Uri.parse('$_origin/api/management.php').replace(queryParameters: {
				'route': route,
				...query,
			});

	Future<Map<String, dynamic>> login(String username, String password) async {
		final response = await _client.post(
			Uri.parse('$_origin/api/auth.php?route=login'),
			headers: const {'Accept': 'application/json', 'Content-Type': 'application/json'},
			body: jsonEncode({'username': username, 'password': password,
				'device_info': 'Maxlond Management / Flutter'}),
		);
		final data = _decode(response);
		if (data['user']?['role'] != 'admin') {
			throw const ApiException(403, 'role_not_allowed', 'هذا التطبيق مخصص للمدير');
		}
		await _storage.write(key: 'access_token', value: data['token'] as String);
		return Map<String, dynamic>.from(data['user'] as Map);
	}

	Future<Map<String, String>> _headers() async => {
		'Accept': 'application/json',
		'Content-Type': 'application/json',
		'Authorization': 'Bearer ${await _storage.read(key: 'access_token') ?? ''}',
	};

	Map<String, dynamic> _decode(http.Response response) {
		final decoded = jsonDecode(utf8.decode(response.bodyBytes));
		if (decoded is! Map<String, dynamic>) {
			throw const ApiException(500, 'invalid_response', 'استجابة الخادم غير صالحة');
		}
		if (response.statusCode < 200 || response.statusCode >= 300 || decoded['success'] != true) {
			final error = decoded['error'];
			throw ApiException(response.statusCode,
				error is Map ? '${error['code'] ?? 'request_failed'}' : 'request_failed',
				error is Map ? '${error['message'] ?? 'تعذر تنفيذ الطلب'}' : 'تعذر تنفيذ الطلب');
		}
		return Map<String, dynamic>.from(decoded['data'] as Map);
	}

	Future<dynamic> get(String route, [Map<String, String> query = const {}]) async {
		final response = await _client.get(_uri(route, query), headers: await _headers());
		return _decode(response);
	}

	Future<dynamic> post(String route, Map<String, dynamic> body) async {
		final response = await _client.post(_uri(route), headers: await _headers(), body: jsonEncode(body));
		return _decode(response);
	}

	Future<void> logout() async {
		try { await post('logout', const {}); } finally {
			await _storage.delete(key: 'access_token');
		}
	}
}

استخدم استدعاء get('reports', {'id':'28'}) أو post('site-save', payload). عالج SocketException والمهلة برسالة قابلة لإعادة المحاولة، ولا تعِد POST ماليًا تلقائيًا إذا كانت نتيجة الطلب غير معروفة.

الصلاحيات والأخطاء

أكواد HTTP200 نجاح، 201 إنشاء، 400 JSON/مسار غير صالح، 401 توكن أو بيانات دخول، 403 صلاحية، 404 غير موجود، 405 طريقة غير مسموحة، 409 تعارض/سجل مقفل، 422 تحقق، 429 محاولات كثيرة، 500 خطأ خادم.
سجلات ماليةلا تحذف قيودًا مرحلة أو حركات مخزن؛ استخدم قيدًا عكسيًا أو تسوية. لا تسمح بحذف حساب مستخدم أو ذي رصيد.

أوقف جلسة التطبيق وامسح التوكن عند 401. عند 403 لا تكرر الطلب؛ أخفِ الإجراء غير المسموح. لا تعرض رسائل SQL أو stack trace، ولا تسجل كلمات المرور أو التوكن.

لإنشاء دور المحاسب على قاعدة موجودة، شغّل مرة واحدة migrations/20261003_add_accountant_role.sql. لا تستورد database.sql فوق قاعدة مستخدمة؛ يحتوي على أوامر حذف الجداول.

قبل النشر: استخدم HTTPS، واضبط APP_URL وبيانات قاعدة الإنتاج يدويًا. لا ترفع إعداد database.php المحلي كما هو ولا تنقل مفتاح التوقيع بين قواعد البيانات.

Maxlond Management · Flutter
أنت مطور Flutter خبير. أنشئ تطبيق إدارة عربي RTL لشركة Maxlond لإدارة المشاريع المدنية والمقاولات. ابنِ تطبيقًا قابلاً للتشغيل باستخدام Material 3، طبقات واضحة (models, services, screens, state)، ودعم هواتف وأجهزة لوحية. لا تخترع أي endpoint غير الموجود في هذه المواصفات.

الهوية: Maxlond Management. هذا التطبيق للمدير فقط role=admin. لا تخلط صلاحيات المهندس أو المحاسب. المخزن والصيانة يستخدمان admin حاليًا، أما المحاسب فله تطبيق ودور مستقل.

الاتصال:
- API المصادقة: https://YOUR_DOMAIN/api/auth.php?route=
- API المدير: https://YOUR_DOMAIN/api/management.php?route=
- استخدم http وflutter_secure_storage. خزّن Bearer token بشكل آمن، لا تسجله ولا تضع بيانات اعتماد ثابتة.
- أرسل Accept: application/json، وContent-Type: application/json لطلبات JSON.
- POST login إلى auth.php، وبعد النجاح تحقق من data.user.role == admin. إذا لم يكن admin أوقف الدخول إلى التطبيق.
- نفّذ me عند استعادة الجلسة، وlogout عند الخروج ثم امسح التوكن. لا توجد نقطة تجديد؛ التوكن صالح 30 يومًا.
- اعمل ApiException موحدًا للأخطاء؛ 401 خروج إلى الدخول، 403 منع، 404 غير موجود، 409 تعارض، 422 تحقق بيانات، 429 إيقاف المحاولات مؤقتًا، 500 رسالة عامة. عالج انقطاع الشبكة والمهلات دون افتراض أن كل استجابة JSON.

التصميم وتجربة الاستخدام:
- واجهة عربية RTL بالكامل، أرقام/مبالغ منسقة، جداول قابلة للبحث والفلترة، تفاصيل واضحة، وحالات loading/empty/error/offline.
- التنقل: الرئيسية، المشاريع، المهام، التقارير، الموارد، المالية، المستخدمون، الإشعارات.
- لا تسمح بتكرار عمليات POST الحساسة بعد timeout غير محسوم. اطلب تأكيدًا قبل الإلغاء أو تغيير المخزون.
- القيود المرحلة والسجلات المالية غير قابلة للحذف؛ صححها بقيد عكسي. اعرض رسائل عربية مختصرة.

شاشات ومسارات API:
1) لوحة المدير: GET dashboard. اعرض sites, engineers, machinery, pending_reports, inventory_value وtoday_top_engineers. عناصر ترتيب الإنجاز: engineer_id, full_name, score, activity_count, completed_tasks.
2) المواقع: GET sites. إنشاء/تعديل POST site-save بالحقول name, client_name, work_date, start_time, end_time, location, budget, status, manager_id, description؛ أرسل id عند التعديل. حالات الموقع planning/active/paused/completed/cancelled. الإلغاء عبر POST site-cancel {"site_id":ID} ويحفظ السجل كـcancelled.
3) خطط العمل: GET tasks مع site_id/status اختياريين. إنشاء/تعديل POST work-plan-save بالحقول site_id,title,description,assigned_to,is_broadcast,priority؛ إلغاء POST work-plan-cancel {"task_id":ID}. الأولوية low/medium/high/urgent. لا تحذف سجل المهمة.
4) تحديثات المهام: تعرضها من GET tasks؛ تحديث المهندس يتم عبر واجهة engineer ولا ترسل تحديثًا نيابة عنه.
5) التقارير: GET reports مع status/site_id؛ التفاصيل GET reports&id=ID تشمل expenses وreceipts. اعرض الطقس والإنجاز والعمل والمشاكل والسلامة والمصروفات والمرفقات. اعتماد/رفض POST report-review بجسم {"report_id":ID,"decision":"approved|rejected","admin_notes":"..."}. الاعتماد يرحّل مصروف التقرير إلى قيد تلقائي عند توفر الحسابات. لا تراجع تقريرًا غير submitted ولا تكرر القرار.
6) المستخدمون: GET users؛ POST user-save لإنشاء أو تعديل بيانات engineer/accountant. الإنشاء يتطلب full_name,username,email,role,password (10 أحرف على الأقل)، ويمكن phone وspecialization. POST user-status {"user_id":ID,"is_active":0|1}. لا تعرض كلمة المرور مرة أخرى ولا تسمح بتعطيل المدير الحالي.
7) الآليات: GET machinery؛ POST machinery-save لإنشاء/تعديل code,name,plate_number,operator_name,status,hourly_cost,notes؛ POST machinery-status {"machinery_id":ID,"status":"available|in_use|maintenance|out_of_service"}.
8) المخزن: GET warehouse-items (يدعم low=1/category_id)، warehouse-categories، warehouse-moves (يدعم item_id). اكتب item عبر POST warehouse-item-save، category عبر warehouse-category-save، تعطيل مادة عبر warehouse-item-status. حركة POST warehouse-move-create بالحقول item_id,type,quantity,unit_price,site_id,supplier,invoice_number,reason، والنوع in/out/adjust. امنع صرف ما فوق الرصيد؛ الوارد والصادر قد ينشئان قيدًا ماليًا تلقائيًا.
9) الصيانة: GET repairs أو repairs&id=ID (مع parts). POST repair-create/repair-update بالحقول machinery_id,title,description,problem_type,priority,technician_name,workshop,labor_cost,notes,parts؛ كل part فيه part_name,quantity,unit_price. تحديث POST repair-status مع repair_id/status. الحالات pending/in_progress/waiting_parts/completed/cancelled. الطلب المكتمل أو المرتبط بقيد مقفل. إكمال تصليح مكلف يرحّل قيد صيانة.
10) الحسابات: GET accounts وfinancial وjournal وjournal-entry&id=ID. POST account-save وaccount-delete وjournal-create. القيد يجب أن يتوازن (مجموع debit = مجموع credit). امنع حذف الحساب المستخدم أو ذي رصيد؛ لا تعدل قيدًا مرحلًا، استخدم قيدًا عكسيًا.
11) الإشعارات: GET notifications؛ POST notification-read {"notification_id":ID} أو POST notification-read-all دون جسم.
